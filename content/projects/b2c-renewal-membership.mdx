## 문제

임직원·법인 회원은 별도 인증과 만료 관리가 필요했고, 이커머스 이벤트가 GTM에 정합성 없이 수집되고 있었다. 호텔 목록 로딩 시 전역 스피너가 화면 전체를 가렸다.

## 해결

- 회사명·도메인 검색 기반 인증 모달과 서버 만료일 기준 만료 판정, 재인증/일반회원 전환 플로우 구현
- GTM dataLayer 헬퍼를 작성해 view_item, add_to_cart, begin_checkout, purchase 이벤트 정합성 수정
  - 결제 수단이 **사용자가 화면에서 고른 값**으로 수집되고 있었다. 결제창에서 수단을 바꾸면
    분석 데이터와 실제 승인 결과가 어긋난다 — PG 승인 완료 시점의 실제 값으로 교체했다
  - 접속 환경 변수가 로그인 시점에만 선언돼 비로그인 진입 데이터가 통째로 누락되던 것을 상시 수집으로 변경
- 다국어 사용 가이드 문서와 에러 메시지 번역 공통 유틸을 작성하고,
  회원정보 수정 폼 라벨을 공통 컴포넌트(`FormLabel`)로 분리
- 메인 6개 섹션의 로딩 스피너를 고정 높이 섹션 스켈레톤으로 교체해 섹션 코드가 로드되는 동안 자리를 잡아두고,
  호텔 목록 로딩 때 화면 전체를 덮던 전역 스피너는 검색 패널 안 로딩 표시로 대체

## 그 밖에 발견한 것

계정 수정 흐름에서 비밀번호를 화면 간에 잠깐 넘기려고 만든 상태 저장소에 **저장 방식이 명시돼 있지 않아, 기본값대로 브라우저 localStorage에 비밀번호가 영속 저장**되고 있었다. 의도는 임시 보관인데 구현은 영속 저장이었던 셈이다.

저장 자체를 제거하고, **이미 사용자 브라우저에 남아 있을 수 있는 값까지 초기 로드 시 삭제**하도록 했다. 앞으로 안 쌓이게 하는 것만으로는 이미 나간 데이터가 정리되지 않는다.

## 효과

- 이커머스 이벤트 정합성 확보로 분석 데이터 신뢰도 개선
- 인증 만료 판정을 프론트 자체 12개월 계산에서 서버 만료일 기준으로 일원화
- 민감정보의 클라이언트 영속 저장 제거

바우처 노출 조건 정리는 [별도 문서](/projects/voucher-policy-schema)로 정리했다.
