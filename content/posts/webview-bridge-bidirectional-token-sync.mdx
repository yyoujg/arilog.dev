## 배경

앱 안에 웹뷰를 얹은 하이브리드 구조였다. 로그인, 토큰 재발급, 로그아웃 같은 인증 상태가 웹 화면과 네이티브 앱 양쪽에 동시에 존재해야 했다 — 웹에서 로그인하면 앱도 그걸 알아야 하고, 앱에서 토큰을 갱신하면 웹도 새 토큰을 써야 한다.

## 문제 — 표준 브릿지를 쓸 수 없는 환경

React Native 앱이라면 `ReactNativeWebView.postMessage`라는 표준 브릿지가 있다. 하지만 이건 순수 네이티브(Swift/Kotlin) 앱에 웹뷰를 얹은 구조라 이 표준을 쓸 수 없었다. 대신 iOS와 Android가 각각 자신만의 웹뷰-네이티브 통신 방식을 제공하는데, 이 둘이 서로 완전히 다르다.

- **iOS**: WKWebView의 `messageHandlers`를 통해 웹 → 네이티브로 메시지를 보낸다.
- **Android**: `@JavascriptInterface`로 노출한 커스텀 객체(`window.Android.*`)를 웹에서 직접 함수처럼 호출한다.

플랫폼마다 API가 다르니, 웹 쪽 코드에서 분기 처리 없이 하나로 뭉뚱그릴 수 없었다.

## 접근 — 방향별로 다른 메커니즘

동기화해야 할 데이터는 명확했다: 액세스/리프레시 토큰, 멤버십 정보, 로그인/로그아웃 상태. 방향은 두 갈래였고, 각 방향의 구현 방식도 서로 달랐다.

두 방향 모두 내가 처음 만든 게 아니다. 앱 -> 웹 전역 함수는 2024년 1월에, 웹 -> 앱 토큰 전달은 2024년 4월에 동료가 먼저 넣었다. 내 작업은 2024년 6~7월, 흩어져 있던 axios 인스턴스를 하나로 병합하면서 토큰 전달 코드를 옮기고, 일반 로그인과 회원가입 흐름에서 갈라져 있던 앱 분기를 정리한 것이다.

**웹 -> 앱** (웹에서 네이티브 함수를 호출):

```
// iOS
window.webkit.messageHandlers.callbackHandler.postMessage({
  type: 'setTokenInfo',
  accessToken,
  refreshToken,
});

// Android
window.Android.setTokenInfo(accessToken, refreshToken);
```

iOS 핸들러 이름은 당시 `callbackHandler`였고, 2024년 12월에 앱 쪽 변경에 맞춰 `callbackHandler0`으로 바뀌었다.

**앱 -> 웹** (네이티브가 전역 함수를 직접 호출):

```
// 네이티브가 웹뷰의 JS 컨텍스트에 주입해둔 전역 함수를 직접 실행
window.setAccessToken = (accessToken, refreshToken) => {
  // 새 토큰을 웹 쪽 상태에 반영
};
window.setUserMembershipInfo = (info) => {
  // 멤버십 정보 갱신
};
```

주목할 점은 앱 -> 웹 방향이 이벤트 리스너를 등록해서 "받는" 구조가 아니라, **네이티브가 웹뷰에 미리 정의된 전역 함수를 찾아 직접 호출하는** 구조라는 것이다. 웹 쪽은 그 함수들을 전역에 미리 걸어두기만 하면 되고, 언제 호출될지는 네이티브 쪽 타이밍에 달려 있다.

## 결과

- axios 인스턴스를 하나로 합치면서, 토큰 갱신 후 앱에 새 토큰을 넘기는 코드도 그 인스턴스 한 곳으로 모였다.
- 다만 플랫폼별 호출을 하나의 유틸 뒤로 감추지는 못했다. `Android` / `webkit.messageHandlers`를 직접 부르는 파일이 지금도 9개 남아 있어서, 화면 코드가 여전히 플랫폼을 알고 있다.

## 배운 점

- **표준이 없는 영역에서는 경계가 저절로 생기지 않는다.** RN 같은 표준 브릿지가 없으니 호출부가 필요한 자리마다 플랫폼 분기를 직접 썼고, 그 결과가 9개 파일에 흩어진 호출이다. 인스턴스 병합으로 한 곳은 모았지만, 나머지를 감싸는 일은 남아 있다.
- **양방향 동기화는 "누가 먼저 알려주는가"를 방향마다 따로 봐야 한다.** 웹 -> 앱은 웹이 호출하는 능동적 구조지만, 앱 -> 웹은 네이티브가 웹의 준비 상태(전역 함수가 이미 정의돼 있는지)에 의존하는 구조라 타이밍을 따로 신경 써야 한다. 동료가 만든 코드를 옮기면서 이 차이를 읽게 됐다.
