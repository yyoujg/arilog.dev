> 관련 프로젝트: [운영 어드민 단독 구축](/projects/ops-admin-standalone)

운영 어드민은 운영자 역할에 따라 들어갈 수 있는 화면이 달랐다. 문제는 "역할이 몇 개냐"가 아니라, **그 접근 판정을 어디에 둘 것인가**였다.

2023년 11월 이 작업을 할 때 역할은 `CS`, `MASTER`, 그리고 그 외(기본) 세 갈래였다. 이후 2024년 1월에 `ADMIN`과 `FNB`, 2024년 8월에 `HOTEL`이 더해져 역할 5종이 됐다. 5종은 위아래가 있는 서열이 아니라, 각자 볼 수 있는 화면 묶음이 다른 역할이다.

## 문제 — 화면마다 심는 권한 체크는 누락된다

화면(컴포넌트) 안에서 "이 화면은 이 역할만" 같은 조건을 렌더 로직에 끼워 넣는 방식도 가능했다. 당장은 동작하지만, 화면이 늘어날수록 비용이 드러나는 방식이다. 당시 라우트는 17개 정도였다.

- **새 화면을 추가할 때 권한 체크를 빠뜨려도 아무도 알아채지 못한다.** 컴파일도, 실행도 정상이다. 그냥 "권한 없는 사용자도 들어가지는" 화면이 하나 생길 뿐이다.
- **어떤 화면에 어떤 권한이 필요한지 한눈에 안 보인다.** 확인하려면 컴포넌트 트리를 하나씩 열어봐야 한다.
- **같은 권한 조건이 여러 화면에 중복**된다. 조건이 바뀌면 그 조건이 박힌 모든 컴포넌트를 찾아 고쳐야 한다.

사람이 매번 기억해야 하는 규칙은 언젠가 빠진다.

## 접근 — 역할별로 등록할 라우트 목록을 나눈다

권한 판정을 라우터로 모았다. 쿠키에 저장된 역할을 읽고, `switch (role)`로 역할마다 **등록할 라우트 목록 자체를 다르게** 렌더한다.

```tsx
// 구조 요약 (실제 라우터를 줄인 것)
const renderRoleRoutes = () => {
  switch (role) {
    case "CS":
      return (
        <>
          <Route index element={<Home />} />
          <Route path="reservations" element={<Reservations />} />
        </>
      );
    case "MASTER":
      return (
        <>
          <Route index element={<Home />} />
          <Route path="hotel/facility" element={<Facility />} />
          {/* ... 시설·객실·패키지·요금·채널·예약 라우트 ... */}
          <Route path="manage/user" element={<Manage />} />
        </>
      );
    default:
      return <>{/* MASTER에서 사용자 관리만 뺀 목록 */}</>;
  }
};
```

어떤 역할의 목록에 없는 경로는 아예 라우트로 등록되지 않으니, 주소를 직접 쳐서 들어와도 그 화면이 렌더되지 않는다. 숫자 레벨을 비교하는 구조가 아니라, **역할마다 허용 화면을 나열**하는 구조다.

다만 컴포넌트 안의 역할 분기가 사라진 건 아니다. 하루 전 같은 권한 작업에서 손본 공통 타이틀 컴포넌트에는 "예약 화면에서 `CS`가 아니면 버튼을 보인다" 같은 버튼 단위 분기가 있고, 메뉴(Nav)도 역할에 따라 보이는 항목을 따로 나눈다. 라우터가 막는 건 **화면 진입**이고, 화면 안의 버튼이나 메뉴 노출은 여전히 컴포넌트가 판단한다.

## 왜 라우팅 단위인가

- **진입점이 하나다.** 화면으로 들어가는 경로는 라우팅을 반드시 거친다. 진입 판정을 거기 두면 화면 쪽에서 체크를 빠뜨려도 들어올 수 없다.
- **역할별 화면 목록이 한 파일에 모인다.** "이 역할은 어떤 화면을 보는가"를 라우터 파일 하나에서 확인할 수 있다.

대신 한계도 분명했다. 역할마다 라우트 목록을 통째로 복제하는 구조라, 역할이 3갈래에서 5종으로 늘면서 같은 `Route` 줄이 역할 수만큼 반복됐다. 화면 하나를 추가하면 그 화면을 볼 역할의 목록마다 같은 줄을 넣어야 하고, 하나를 빠뜨리면 그 역할만 조용히 못 들어간다. 누락 위험이 컴포넌트에서 라우트 목록으로 옮겨 갔을 뿐 없어지지는 않았다.

## 정리

| 구분             | 화면마다 체크하는 방식      | 역할별 라우트 목록 (실제 구조)                  |
| ---------------- | --------------------------- | ----------------------------------------------- |
| 진입 판정 위치   | 화면마다 흩어짐             | 라우터의 `switch (role)` 한 곳                  |
| 목록에 없는 경로 | 체크를 빠뜨리면 조용히 통과 | 라우트가 등록되지 않아 렌더되지 않음            |
| 역할별 화면 파악 | 컴포넌트 트리를 일일이 확인 | 라우터 파일 하나로 조망                         |
| 화면 추가 시     | 화면 안에 체크 추가         | 볼 수 있는 역할의 목록마다 `Route` 한 줄씩 추가 |
| 버튼·메뉴 노출   | 컴포넌트가 판단             | 여전히 컴포넌트(타이틀, Nav)가 판단             |

권한 체크는 "빠짐없이 챙기는 성실함"으로 지켜지지 않는다. 진입 판정을 반드시 거치게 되는 라우터로 옮긴 건 맞는 방향이었다. 다만 역할별로 목록을 복제하는 방식은 역할이 늘어나자 다시 "사람이 매번 맞춰 넣어야 하는" 구조가 됐다. 판정 위치를 옮기는 것과, 판정 규칙을 중복 없이 선언하는 것은 별개의 문제라는 걸 역할이 5종이 된 뒤에야 체감했다.
