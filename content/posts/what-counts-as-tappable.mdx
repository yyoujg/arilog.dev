Moneytermi에 전역 탭 진동을 붙이면서 "누를 수 있는 것"을 코드로 정의해야 했다. 결국 CSS 셀렉터
한 줄이 그 정의가 됐다. 이 글을 읽고 그 한 줄이 무엇을 기준으로 삼았고 무엇을 놓쳤는지 다시 봤다.

## 아티클 요약: 인터랙티브는 한 가지 성질이 아니다

글은 MDN 문서의 한 문장에서 시작한다. `dialog` 요소가 인터랙티브 요소가 아니라는 설명인데,
저자는 이것이 틀렸다고 본다. 사용자가 다룰 수 있는 요소이고, 포커스를 받을 수 있기 때문이다.

핵심은 "인터랙티브하다"를 세 가지로 쪼개 보는 것이다.

- 포커스 가능: 스크립트로 `focus()`를 호출했을 때 포커스를 받을 수 있다.
- 탭 이동 가능: Tab 키 순서에 들어간다.
- 클릭 포커스: 마우스로 눌렀을 때 포커스가 간다.

세 성질은 따로 움직인다. `tabindex="-1"`을 주면 포커스는 가능하지만 탭 순서에서는 빠진다. 저자는
이 값을 쓰는 것 자체는 괜찮다고 본다. 다만 `div`나 `h2`에 `tabindex="0"`을 줘서 탭 순서에 넣는
식으로 버튼을 흉내 내지 말고, 처음부터 `button`을 쓰라고 한다.

또 어떤 요소가 포커스 가능한 영역이 되려면 조건이 붙는다. 비활성화(`disabled`) 상태가 아니어야
하고, `inert` 안에 있지 않아야 하고, 실제로 렌더링되고 있어야 하는 식이다.

## 내 사례: 전역 탭 진동의 셀렉터

### 1. 누를 수 있는 것을 시맨틱으로 판정했다

09-25에 앱 전체의 버튼 누름에 짧은 진동을 붙였다(`55e584c`). 화면마다 진동 호출을 넣는 대신
`document`에 `pointerdown` 리스너를 하나 걸고, 눌린 요소에서 가장 가까운 "누를 수 있는 것"을
찾는 방식이다. 그 정의가 아래 셀렉터다.

```ts
const TAPPABLE =
  'button, [role="button"], [role="switch"], [role="tab"], a[href], input[type="checkbox"], input[type="radio"]';

const el = (e.target as Element | null)?.closest?.(
  TAPPABLE,
) as HTMLElement | null;
if (!el) return;
if (
  (el as HTMLButtonElement).disabled ||
  el.getAttribute("aria-disabled") === "true"
)
  return;
feedbackTick();
```

클래스 이름이나 `onClick` 유무를 보지 않고, 요소와 role만 본다. `href` 없는 `a`는 빠진다.
그리고 비활성 버튼과 `aria-disabled="true"`는 진동하지 않게 했다. 아티클이 말한 포커스 가능 영역의
조건 중 "비활성이 아닐 것"과 같은 판단을 손으로 한 셈이다.

### 2. 구형 웹뷰에서 `:has()`가 터졌다

처음 셀렉터에는 체크박스를 감싼 `label`도 넣었다. `label:has(> input[type="checkbox"])`이다.
같은 날 버그 점검(`a829d2a`)에서 이 항목을 뺐다. 구형 웹뷰에서 `:has()`를 모르면 `closest()`가
셀렉터 파싱 단계에서 예외를 던진다. 셀렉터 목록은 하나라도 틀리면 전체가 무효라서, 코드상으로는
그런 웹뷰에서 모든 탭마다 예외가 나고 진동이 전부 빠지는 구조였다. 지금 코드에는 그 이유가 주석으로 남아 있다.

`label`을 빼도 체크박스 자체는 `input[type="checkbox"]`로 잡힌다. 라벨 글자를 눌렀을 때만 진동이 빠진다.

### 3. 눌릴 것처럼 보이는 `div`

09-22에는 반대 방향의 문제가 있었다. 단어 카드의 뉴스 목록에서 링크를 지우고 `<div>`로 바꿨는데,
카드 안에 굵은 제목이 나열된 모양이라 여전히 눌릴 것처럼 보였다. 커밋(`2c57ff2`) 메시지에 따르면
`active`, `hover`, `cursor` 계열 클래스와 아이콘은 이미 0건이었다. 그래서 `gap` 간격 대신
`divide-y` 구분선과 `py-3`로 읽기용 리스트임을 드러냈다.

이 목록은 이후 검수 반려로 다시 외부 링크가 됐고, 지금은 `<button type="button">`이다. 눌리는
요소가 되자 `button`으로 돌아왔고, 셀렉터에도 자동으로 들어간다.

### 4. `disabled`를 믿지만 한 번 더 막는다

코스 화면의 잠긴 노드는 `<button type="button" disabled={locked}>`이다. 그런데 탭 핸들러 첫 줄에는
이렇게 적어 두었다(`src/pages/CourseScreen.tsx` 212행).

```ts
// disabled 버튼은 click이 안 오지만, 웹뷰/리셋 CSS에 따라 새는 경우가 있어 한 번 더 막는다.
if (node.state === "locked") return;
```

"새는 경우"를 재현한 기록은 커밋이나 출시 노트에서 찾지 못했다. 방어 코드로 읽어야 한다.

### 5. 상태도 속성으로

09-25 이모지 선택 시트(`5b62ff7`)에서는 각 버튼에 `aria-label`(`아바타 ${emoji}`, 예: "아바타 🦝")과
`aria-pressed`(현재 선택 여부)를 붙였다. 선택 상태를 색으로만 보여주지 않고 버튼의 상태로 노출한 것이다.

블로그 썸네일 메이커에서도 같은 일을 했다. 06-18 커밋(`17e1b7d`)에서 색상 스와치와 옵션 버튼에
`aria-pressed`를 달고, 링크와 버튼 전반에 `focus-visible` 링을 넣었다. 마우스로 누를 때는 링이 안
보이고 키보드로 이동할 때만 보이게 하는 방식이다.

## 아티클과 내 코드를 한 표로

| 아티클의 구분               | 내 코드                                      | 상태                                 |
| --------------------------- | -------------------------------------------- | ------------------------------------ |
| `button`을 써라             | 셀렉터가 `button`과 role을 기준으로 판정     | 뉴스 항목은 결국 `button`으로 정리   |
| 비활성은 포커스 영역이 아님 | `disabled`, `aria-disabled="true"` 진동 제외 | 핸들러에서 한 번 더 막음             |
| `inert`는 포커스 영역 아님  | 처리 없음                                    | `src`에 `inert`, `tabIndex` 사용 0건 |
| `div`를 버튼처럼 쓰지 마라  | `onClick`이 걸린 `div` 5곳(한 줄 grep 기준)  | 모달 배경, 툴팁 닫기, 주간 리캡      |
| 탭 이동과 포커스는 별개     | 키보드 탭 순서는 따로 점검하지 않음          | 미검증                               |

## 다른 점과 한계

아티클의 기준은 키보드와 보조기술이다. 내 셀렉터는 손가락 탭에 진동을 줄지 정하는 용도라 출발점이
다르다. 그래도 "누를 수 있는가"를 요소의 의미에 맡기니 정의가 한 줄로 끝났고, 이 점은 아티클의
`button`을 쓰라는 조언과 같은 방향이었다.

반대로 시맨틱 밖에 있는 것은 그대로 빠진다. 한 줄 grep으로 찾은, `onClick`이 걸린 `div` 5곳 중 주간 리캡은 화면 전체를
눌러 다음 장으로 넘기는 실제 상호작용인데, 셀렉터에 걸리지 않아 진동이 없고, 코드상 키보드 포커스도 받지 않는다.
나머지는 모달 배경 닫기, 툴팁 닫기, 이벤트 전파를 막는 대화상자 래퍼다.

접근성 점수나 스크린 리더 동작은 실측하지 않았다. 이 글의 판단은 코드와 커밋 기록만 근거로 한다.

## 배운 점

- "누를 수 있는 것"의 정의를 시맨틱 요소와 role에 맡기면 판정 코드가 짧아지고, 시맨틱을 지키지 않은 곳이 저절로 드러난다.
- 전역 리스너 안의 셀렉터는 가장 오래된 웹뷰 기준으로 쓴다. 파싱 실패는 한 요소가 아니라 리스너 전체를 멈출 수 있다.
- 눌리지 않는 요소는 눌릴 것처럼 보이지 않게, 눌리는 요소는 `button`으로. 둘 사이의 `div`가 가장 애매했다.
